# Ночная проверка CargonaOS — 4 октября 2026

Работа выполнена в репозитории; production-сервер, его данные и настройки не менялись. Время — Asia/Yekaterinburg. Общий локальный прогон начат в 02:31, близко к запрошенным 02:33; результат дополняется после выполнения.

## Завершённые этапы

- Шифрованные внешние копии Restic, B2/HTTPS S3, таймер и retention; расшифровка только в новый закрытый каталог.
- Пробное восстановление JSON и полный `pg_restore` в новой internal-only Docker-сети; запуск и перезапуск восстановленного API. Контейнеры и их временные тома удаляются.
- Мониторинг API/хранилища, webhook/очереди ботов, OOM, свободных диска/памяти, свежести и ошибок бэкапа; уведомления в личный Telegram при изменении состояния и восстановлении.
- Установка из Compose и готовых образов без клонирования, сборки исходников или установки Node на сервер; обновление CLI с сохранением прежних файлов и прав исполнения.
- Обслуживание через CLI с копией, остановкой писателя и проверкой API перед возвратом внешнего доступа.

## Найденные проблемы и исправления

| Проблема | Последствие | Исправление / проверка |
|---|---|---|
| Старый CLI сбрасывал пароль владельца прямой записью JSON при работающем API; вставлял пароль в JS-строку и печатал его | Потеря конкурентных изменений, неприменённый сброс в PostgreSQL, утечка секрета | Отдельный offline maintenance CLI, общий lock, копия перед остановкой; stdin, scrypt, отзыв сессий, аудит; ошибку не объявляет успехом |
| CLI импорт запускался независимым writer рядом с API | Конфликт PG lease или перезапись JSON; код искал исходники/Node на сервере | Только контейнерный импорт после остановки API; read-only mount каталога источника; возврат после readiness |
| Перезапуск контейнера после изменения `.env` не перечитывал значения, а ошибки иногда скрывались | Лимит/домен могли не примениться при сообщении об успехе | `up --no-deps --no-build --pull never` для пересоздания с новой конфигурацией; убрано игнорирование ошибки |
| `.env` редактировался через sed со значением пользователя | Символы пароля могли ломать файл/подстановку | Atomic replacement, single-quoted dotenv, проверка перевода строк; тест специальных символов и Compose |
| При первом взвешивании API полагался на цену интерфейса | Устаревший клиент мог сохранить неправильный тариф | При настроенном тарифе ПВЗ/компании цена рассчитывается сервером; отрицательные/нечисловые суммы отклоняются; существующая стоимость сама не пересчитывается |
| Известный `password123` допускался как пароль платформы и был fallback Compose | Доступ с публично известными реквизитами при незаполненной настройке | Fallback удалён; известное значение не даёт вход и не сохраняет действительность старой сессии; отрицательный тест |
| Webhook подставлял домен NOOR при отсутствии корректного публичного домена | Другой компании можно было настроить чужой webhook | Требуется настроенный публичный домен, ошибка вместо чужого адреса |

Отдельно проверяются ошибки загрузки бэкапа: не меняют last-success, оставляют ненулевой код, очищают временную расшифрованную копию. Повторные уведомления подавляются, неудачная отправка повторяется. Это проверки новых механизмов, а не заявление об обнаруженном production-инциденте.

## Что требует отдельного запуска оператора

Ключей внешнего хранилища и копии настоящей базы нет. Подключение B2/S3, включение таймеров, тест внешних уведомлений и репетиция на реальном объёме не проводились. RPO/RTO и окно переключения не подтверждены. Переключение production на PostgreSQL и переход существующего сервера на runtime Compose остаются согласованными операциями; их инструкция готова, автоматически они не запускаются.

Без внешнего uptime-monitor внутренний монитор не обнаружит полное выключение самого сервера. Внешняя копия не содержит Docker-образов и загрузок, поэтому для восстановления нужны сохранённая версия образов и отдельная политика хранения таких файлов. Исторические образы без декларации совместимости требуют отдельной репетиции отката.
