# Зашифрованные копии вне сервера

`offsite-backup.sh` использует установленный на хосте Restic и systemd. Требуются Linux, Docker Compose v2, util-linux (`flock`) и Restic >= 0.16. CLI не устанавливает пакеты и не включает расписание автоматически.

Оператор создаёт отдельный закрытый bucket B2 и application key с доступом только к этому bucket (чтение, запись, список и удаление для retention). Настройка:

```bash
cargona offsite:configure
cargona offsite:init
cargona offsite:run
cargona offsite:list
cargona offsite:check
cargona offsite:enable
```

Пароль шифрования и ключ вводятся скрыто; файл `data/offsite/restic.env` имеет права 600. Пароль нужно сохранить отдельно от сервера: без него копии не восстановить. Этот каталог исключён из Git. Уже существующий репозиторий не нужно повторно инициализировать. Для HTTPS S3 допускается ручная настройка этого файла: `RESTIC_REPOSITORY=s3:https://endpoint/bucket/path`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `RESTIC_PASSWORD`; значения без кавычек, по одному на строку. Файл не выполняется как shell-код.

Расписание: каждые 15 минут после запуска предыдущего задания, таймаут 14 минут. Одновременно с обновлением или ручной копией запуск блокируется общим flock; следующий timer попробует снова. Приложение не останавливается. JSON копируется через открытый inode атомарно заменяемого файла, проверяется структура; PostgreSQL — `pg_dump -Fc` с согласованным snapshot и проверкой каталога `pg_restore --list`. Поддерживается локальный postgres из Compose; несовпадение базы с реальным API блокирует копию.

Копия содержит состояние/дамп, resolved Compose с секретами, `.env` при наличии, режим хранения, ID образа API, его registry digests (если образ был загружен из registry) и SHA256 файлов. Restic шифрует содержимое перед отправкой. Временные незашифрованные файлы удаляются при обычном завершении и ошибках; аварийное выключение может оставить staging-каталог, доступный только владельцу. Образы Docker, загрузки и сертификаты Caddy в эту копию не входят. Конфигурация и данные снимаются отдельно; не редактируйте настройки во время задания.

После успешной отправки, не чаще раза в день, retention сохраняет все копии за последние 24 часа, 14 дневных, 8 недельных и 12 месячных. Удаление ограничено tag `cargona`, host `cargona` и текущим абсолютным путём snapshot; после переноса каталога прежние группы нужно обслуживать отдельно. Не используйте тот же bucket/prefix для другой установки. Изменение времени хранения и удаление версий на стороне B2 не должно удалять объекты Restic независимо от его retention.

`cargona offsite:status` показывает последнюю удачную отправку и код последней попытки; журналы: `journalctl -u cargona-backup.service`. `offsite:disable` отключает будущие задания; уже запущенное задание завершается. `offsite:check` читает и проверяет весь репозиторий, может требовать времени и платного трафика. Не запускайте `restic unlock` при работающем задании.

Это не гарантия RPO 15 минут: ошибки сети, lock, долгий дамп или переполненный диск могут нарушить период. Проверка каталога дампа и Restic не заменяет восстановление в отдельную PostgreSQL и проверку приложения. Пробное восстановление и мониторинг описаны в [runtime-operations.md](runtime-operations.md). Перезапись рабочей базы этим инструментом не поддерживается.

Официальная документация: [хранилища, ключи и шифрование Restic](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html), [правила хранения](https://restic.readthedocs.io/en/stable/060_forget.html).
